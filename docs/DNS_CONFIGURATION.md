# DNS Configuration for quantummint.net

## Overview
This document provides the DNS records needed for Sierra Books email system at `quantum.quantummint.net`.

## Required DNS Records

### 1. SPF Record
**Purpose**: Specify which mail servers are authorized to send email on behalf of your domain.

```
Type: TXT
Host: @
Value: v=spf1 include:_spf.quantummint.net include:sendgrid.net ~all
TTL: 3600
```

**Explanation**:
- `v=spf1` - SPF version 1
- `include:sendgrid.net` - Authorize SendGrid servers (update if using different provider)
- `~all` - Soft fail for unauthorized servers (use `-all` for hard fail once confirmed working)

### 2. DKIM Records
**Purpose**: Add cryptographic signature to verify email authenticity.

> [!IMPORTANT]
> DKIM keys must be generated by your email service provider (SendGrid/Mailchimp).
> Add the keys they provide below:

**SendGrid DKIM** (Get from SendGrid dashboard):
```
Type: CNAME
Host: s1._domainkey.quantummint.net
Value: [VALUE PROVIDED BY SENDGRID]
TTL: 3600

Type: CNAME  
Host: s2._domainkey.quantummint.net
Value: [VALUE PROVIDED BY SENDGRID]
TTL: 3600
```

**Mailchimp DKIM** (Get from Mailchimp dashboard):
```
Type: CNAME
Host: k1._domainkey.quantummint.net
Value: dkim.mcsv.net
TTL: 3600
```

### 3. DMARC Record
**Purpose**: Specify how receiving servers should handle emails that fail SPF/DKIM checks.

```
Type: TXT
Host: _dmarc.quantummint.net
Value: v=DMARC1; p=none; rua=mailto:reports@quantummint.net; ruf=mailto:forensics@quantummint.net; fo=1
TTL: 3600
```

**Explanation**:
- `p=none` - Monitor only mode (change to `quarantine` or `reject` after testing)
- `rua=mailto:reports@quantummint.net` - Aggregate reports destination
- `ruf=mailto:forensics@quantummint.net` - Forensic reports destination
- `fo=1` - Generate reports if any authentication mechanism fails

### 4. MX Records (For Receiving Email)
**Purpose**: Direct incoming emails to the correct mail server.

```
Type: MX
Host: @
Priority: 10
Value: mail.quantummint.net
TTL: 3600
```

> [!NOTE]
> If using Google Workspace or Microsoft 365, use their MX records instead.

### 5. Subdomain Email Addresses

Create A or CNAME records for email subdomains if needed:

```
Type: A
Host: mail
Value: [YOUR SERVER IP]
TTL: 3600
```

## Verification Steps

### 1. After Adding DNS Records

Wait 24-48 hours for DNS propagation, then verify:

**Check SPF Record**:
```bash
nslookup -type=txt quantummint.net
# Should show: v=spf1 include:sendgrid.net ~all
```

**Check DMARC Record**:
```bash
nslookup -type=txt _dmarc.quantummint.net
# Should show: v=DMARC1; p=none; ...
```

**Check MX Record**:
```bash
nslookup -type=mx quantummint.net
```

### 2. Online Verification Tools

Use these tools to verify DNS configuration:
- **MX Toolbox**: https://mxtoolbox.com/SuperTool.aspx
- **DMARC Analyzer**: https://www.dmarcanalyzer.com/
- **Mail Tester**: https://www.mail-tester.com/

### 3. SendGrid/Mailchimp Verification

- **SendGrid**: Go to Settings → Sender Authentication → Verify domain
- **Mailchimp**: Go to Settings → Domains → Verify domain

## Security Best Practices

1. **Start with Monitoring**
   - Use `p=none` in DMARC initially
   - After 2-4 weeks of monitoring reports, upgrade to `p=quarantine`
   - After another 2-4 weeks, upgrade to `p=reject`

2. **Monitor DMARC Reports**
   - Check aggregate reports weekly
   - Investigate any unauthorized senders
   - Use a DMARC monitoring service like Postmark or Valimail

3. **Regular Testing**
   - Send test emails monthly
   - Check spam score with Mail Tester
   - Verify deliverability to major providers (Gmail, Outlook, Yahoo)

4. **Keep Records Updated**
   - Review SPF includes quarterly
   - Update DKIM keys if changing email providers
   - Keep contact information in DMARC records current

## Troubleshooting

### Emails Going to Spam

1. Check SPF alignment
2. Verify DKIM signatures are present
3. Test spam score at mail-tester.com
4. Ensure reverse DNS (PTR) is set correctly
5. Check if domain/IP is on any blacklists

### DMARC Failures

1. Verify SPF and DKIM are passing
2. Check domain alignment (From domain must match SPF/DKIM domains)
3. Review DMARC aggregate reports for failure reasons

### Delivery Issues

1. Verify MX records point to correct server
2. Check if port 25 is open on your server
3. Ensure SPF includes all sending servers
4. Test with https://www.mail-tester.com/
